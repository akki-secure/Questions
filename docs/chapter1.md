## 第1章 インターネットとネットワークの仕組み（12問）

### Q1. インターネットとは
質問:
「インターネット」と「Webブラウザで見るホームページ」は同じものですか？違うとすれば、どう違いますか？

答え:
違うもの
理由:
1.インターネットとは、コンピュータ同士を繋げるもの。

2.ホームページとは、Webサイト全体のこと。もしくは、Webサイトのトップページのこと。

### Q2. IPアドレスとポート番号
質問:
このプロジェクトではフロントエンドを `localhost:5173`、バックエンドを `localhost:8080` で起動しています。
1.`localhost`とは何を指しますか？
2.`:5173` や `:8080` のようなポート番号はなぜ必要ですか？

答え:
1.localhostとは、自分が使っているパソコン。

2.ポート番号の`localhost:5173`はフロントエンド、`localhost:8080` はバックエンドと区別することにより、1つのパソコンで、複数のアプリが同時に動いても、OSが通信を正しいアプリに届けられるからです。

### Q4. HTTPとは
質問:
1.HTTPとは何の略で、どのような役割を持つものですか？

2.「プロトコル」という言葉の意味も含めて説明してください。


答え:
1.Hypertext Transfer Protocolの略。
暗号化されていない状態
ポート番号:80
サイトや動画などを見たりできる。


2.WebブラウザとWebサーバが、Webページ（HTML）や画像などのデータをやり取りするためのプロトコル。



---

### Q5. HTTPとHTTPSの違い
質問:

1.HTTPとHTTPSの違いは何ですか？

2.なぜ現在のWebサイトはほぼすべてHTTPSを使用していますか？

答え:
1.HTTPとは、ポート番号:80で、暗号化されていないので、(サーバー証明書を持っていない)本人確認ができない、WebブラウザとWebサーバが、Webページ（HTML）や画像などのデータをやり取りするためのプロトコル。

2.HTTPSとは、ポート番号:443で、SSL/TLS(サーバー証明書の本人確認が可能)により暗号化され、信頼できるWebブラウザとWebサーバが、Webページ（HTML）や画像などのデータをやり取りするためのプロトコル。
WiresharkやnmapやBurpSuiteなどツールが悪用された場合、HTTPのままだと盗聴や改ざんやなりすましという危険があるから。

### Q6. リクエストとレスポンス
質問:
Webにおける「リクエスト」と「レスポンス」の関係を、日常生活の例えを使って説明してください。

答え:
リクエストとは、注文すること。
レスポンスとは、提供すること。
(例)資さんうどんで、注文から提供するまでの流れ
お客様(ユーザー)が、資さんうどんで、ごぼう天うどん(エンティティ)を食べたい時、店員(サーバー)に対して、注文(リクエスト)をお願いしました。
店員は(サーバー)が、ごぼう天うどん(エンティティ)を提供(レスポンス)しました。

### Q7. HTTPメソッド
質問:
このアプリのAPIでは以下を使っています。
- GET
- POST
- PUT
- DELETE
- PATCH

1.これらの「HTTPメソッド」とは何ですか？

2.日常生活の例えで、それぞれの違いを説明してください。


答え:                            
1.GETとは、データを取得すること。  
2.(例)資さんうどんのメニューにあった注文したごぼう天うどんを受け取る。

1.POSTとは、データを送る(新規登録)こと。
2.(例)資さんうどんのメニューに新しいうどんを載せる。

1.PUTとは、データを更新(変更)すること。
2.(例)資さんうどんで注文したごぼう天うどんを肉うどんに変更してもらう。

1.DELETEとは、データを削除すること。
2.(例)資さんうどんで、注文した肉うどんを取り消す。

1.PATCHとは、データを修正すること。
2.(例)資さんうどんで、注文したごぼう天うどんについているネギありをネギなしにしてもらう。

### Q8. HTTPステータスコード
質問:
サーバーからの返事には「ステータスコード」という3桁の数字が含まれます。

以下のコードはそれぞれ何を意味しますか？

答え:
1.200とは、 データを受け取り、送信が、成功。(OK)
(例)資さんうどんで、注文したごぼう天うどんが、届いた。

2.201とは、データを新規作成が成功。(Created)
(例)お客様が、初めて、資さんうどんの会員登録に新規登録できました。

3.400とは、クライアントエラー(Bad Request)
(例)資さんうどんの店員に、お客様が、メニューにない、ハンバーガーを注文したが、店員は、できないと断った。

4.404とは、データが存在しない。(Not Found)
(例)お客様が、注文した資さんうどんのメニューにバニラシェイクは、存在しない。

5.500とは、サーバー内部エラー。(Internal Server Error)
(例)資さんうどんでお客様が、注文した品が多すぎて、トラブルにより鍋が壊れた。

※HTTPステータスコードを確認する方法
1.Developer Tools(DevTools)を使う。
2.BurpSuiteを使う

### Q11. CORSとは
質問:
フロントエンド（5173）からバックエンド（8080）にアクセスする際、「CORS」という仕組みが関係します。
CORSとは何のためにありますか？

答え:
Cross Origin Resource Sharingの略で、異なるオリジン（ドメイン、プロトコル、ポートの組み合わせ）の間で、安全にデータをやり取りするための仕組みのこと。

###  Q12. クライアントとサーバー
質問:

1.「クライアント」と「サーバー」とは何ですか？

2.このアプリの構成の中で、それぞれどれがクライアントでどれがサーバーですか？
- ブラウザ
- バックエンド
- データベース

答え:
1.クライアントとは、サービスを要求する側
(例)資さんうどんに来たお客様が店員に対して、メニューを注文すること

サーバーとは、サービスを提供する側
(例)資さんうどんに来たお客様が注文したメニューを提供すること。

2.A:ブラウザ　→クライアント
  B:バックエンド　→サーバー
  C:データベース　→サーバー
