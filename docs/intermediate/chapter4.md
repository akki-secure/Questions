## ☁️ 第4章: インフラとデプロイ（5問）

### Q22. Docker / docker-compose

> Dockerの概要と、ローカルインストールとの違いを説明してください。
答え:
1.Dockerとは、アプリとその実行に必要なライブラリ・設定をまとめて「コンテナ」という単位でパッケージ化し、あらゆる開発環境内で同じように起動や停止や削除や実行できるサービスのこと。

2.ローカルインストールとは、自分のパソコン内やプロジェクトフォルダ内に直接ミドルウェアやライブラリをインストールして動かす作業のこと。

3.違いとして、ローカルインストールはホストOSに直接依存するため「自分の環境では動くが他の人の環境では動かない」という問題が起きやすいのに対し、Dockerはコンテナ内に環境を隔離するため、開発者間・本番環境間で動作の一貫性を保ちやすいからです。

### Q23. AWS基本サービス

> EC2 / RDS / ALB / S3 の役割と分離理由を説明してください。
答え：
1.EC2とは、クラウドに存在している仮想マシンのこと。

2.RDSとは、データベースをAWSが代わりに管理・運用してくれるサービスのこと。

3.ALBとは、Webサイトやアプリへのアクセスの負荷を、複数のサーバーに自動で分けて送る仕組みのこと。

4.S3とは、AWSのデータを保存する場所のこと。

5.分離理由：EC2(アプリ実行)・RDS(データ永続化)・ALB(負荷分散・ルーティング)・S3(静的ファイル保存)のように役割ごとにサービスを分けることで、各層を独立してスケールさせやすくなり、障害が起きたときの影響範囲を限定でき、サービスごとに必要最小限の権限（IAM）だけを付与できるため、可用性とセキュリティの両方が向上するからです。

### Q24. IaC（Terraform）

> 手動構築との違いとメリットを説明してください。
答え：
1.手動構築とは、インフラをGUIやコンソールを使って、ユーザーが直接操作して設定する方法であり、逆にIaCは、インフラをコードで管理する方法のこと。

2.変更履歴のバージョン管理・再現性・レビュー可能性や自動化することにより、手動による設定ミスを減らすことができる。

### Q25. 環境変数と機密情報

> ソースコードに直接書く問題点と、安全な管理方法を説明してください。
答え:
1.ソースコードをユーザー自身が直接書くと、ヒューマンエラーやハードコードをうっかりして、直接書いて、ハッカーにより、機密情報を盗まれる危険性があるからです。

2.安全な管理方法として、環境変数（`.env`ファイルなど）で管理し`.gitignore`でGit管理対象から除外する、本番環境ではAWS Secrets ManagerやParameter Storeなどのシークレット管理サービスを使い、アプリケーションには最小権限のIAMロールで取得させることでリスクを最小限にする。

### Q26. 構造化ログ

> JSONログの利点と、MDC（requestId / userId）の役割を説明してください。
答え:
1.JSONログは、キーと値のペアでデータを構造化して記録する形式により、検索や解析の自動化が容易になり、可読性のバランスに優れているというメリットがあります。

2.MDCとは、スレッドごとに固有の情報を保持し、ログ出力時に自動付与する仕組みのこと。
 requestId とは、HTTPリクエスト単位に割り振られる一意の識別子のこと。
 userIdとは、操作を行っているユーザーの識別子のこと。
