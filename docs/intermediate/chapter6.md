### Q32. N+1問題

> 概念と、タイムライン例で説明してください。
答え:
1.N+1問題とは、データベースのクエリをまとめて聞けば1回で済むデータ取得を、わざわざ1件ずつ何度も聞きに行ってしまうデータを無駄に取得する問題のこと。

2.タイムラインの流れ（N=3の例の場合）
0.1秒: アプリがDBへ「全ブログ記事（3件）」を1回で取得するSQLを発行（1回目）
0.2秒: DBから記事A、記事B、記事Cのデータがアプリに返る（計3件 = N）
0.3秒: アプリが記事Aに紐づくコメントを取得するSQLを発行（2回目 / N=1）
0.4秒: DBから記事Aのコメントが返る
0.5秒: アプリが記事Bに紐づくコメントを取得するSQLを発行（3回目 / N=2）
0.6秒: DBから記事Bのコメントが返る
0.7秒: アプリが記事Cに紐づくコメントを取得するSQLを発行（4回目 / N=3）
0.8秒: DBから記事Cのコメントが返る
0.9秒: すべてのデータを結合して画面を表示（合計4回のクエリ：1 + 3

### Q33. ページネーション

> 必要な理由と、代表的な2方式を比較してください。
答え:
1.ページネーションが必要な理由は、全てのページを１つページまとめると通信速度が落ちるので、大量のデータを一度に全部表示せず、少しずつ分けて表示するようにすれば、Webサイトの表示速度やサーバーの負担を軽くできるからです。

2.ページネーションの代表的な2方式
オフセット方式(ページ番号方式)とは、何ページ目を何件表示するやり方のこと。

カーソル方式(無限スクロール向き)とは、X(旧Twitter)やInstagramのタイムラインのように、下にスクロールすると次が読み込まれる方式のこと。

### Q34. 画像アップロード設計

> DB保存とS3保存の違いと利点を説明してください。
答え:
1.DB保存とは、データベースに保存すること。
　利点は、ユーザー情報や注文履歴などの構造化データを高速に検索・更新・管理するのに優れています。


2.S3保存とは、AWSにデータを保存すること。
　利点は、画像や、動画などの大容量ファイルを低コストかつ容量無制限で安全に保管できるからです。

### Q35. APIバージョニング

> 代表的な方式と特徴を説明してください。
答え:
1.URLパス方式とは、URLの中にバージョン番号を直接入力することです。
(例)https://api.example.com/v1/users

2.HTTPヘッダー方式とは、REST設計の原則に近い、リクエストのヘッダーにバージョンを直接入力することです。
(例)Accept: application/vnd.myapi.v2+json

3.クエリパラメータ方式とは、URLの末尾にパラメータとしてバージョンを直接入力することです。
(例)https://api.example.com/users?version=2

３つともDevToolsで、確認することもできる。

### Q36. 技術選定

> 判断基準を説明し、
答え:
技術選定とは、システム開発で使う言語やツールを選ぶことです。

判断基準は、要件への適合性（必要な機能・性能を満たせるか）、チームの習熟度や学習コスト、コミュニティ・エコシステムの大きさ（情報量やライブラリの豊富さ）、将来的なスケーラビリティや保守のしやすさ、採用実績や長期的なサポートの有無などを総合的に比較して選ぶことです。
> 
> React + Spring Boot + PostgreSQL を例に具体化してください。
答え:
(例)勤怠管理アプリ
1.Reactでは、ユーザーが操作する、ログイン画面などのフォームやボタンなどのフロントエンドの部品を作るJavaScriptのライブラリ。コミュニティが大きく学習コストを抑えやすい。

2.Spring Bootでは、PostgreSQLのクエリを使って、設定やReactで、処理するコードを書く、アプリを作るJavaのフレームワーク。実務での採用実績が豊富で長期保守がしやすい。

3.PostgreSQLでは、データを保存するデータベースを作ることをする高機能データベース。勤怠データのような正確性が求められる構造化データを扱うのに適している。
